# Como contribuir

Obrigado pelo interesse em colaborar com os projetos da **Solution IPD**.

Estas orientações são um ponto de partida. **As regras, permissões e instruções do repositório específico prevalecem**. A existência de um repositório visível não implica, por si só, autorização para reutilizar seu código.

## Antes de começar

1. Leia o README, a documentação e as condições de uso do projeto.
2. Procure issues ou pull requests existentes para evitar trabalho duplicado.
3. Para propostas maiores, abra uma issue (quando habilitada) e descreva o problema e o resultado esperado.
4. Não publique credenciais, chaves de API, dados de clientes, informações pessoais ou outros materiais confidenciais.

## Issues úteis

Ao relatar um problema, informe, quando possível:

- Contexto e componente afetado.
- Passos para reproduzir e resultado esperado versus observado.
- Ambiente ou versão relevante.
- Logs mínimos, previamente revisados para remover informações sensíveis.

Para sugestões de melhoria, descreva a necessidade, a proposta e alternativas consideradas.

## Pull requests

- Mantenha a mudança focada e explique **por que** ela é necessária.
- Relacione a issue correspondente, quando existir.
- Descreva como testou ou validou a alteração; quando não for possível testar, explique a limitação.
- Atualize documentação e exemplos quando a mudança afetar o uso do projeto.
- Observe o estilo de código, os fluxos de aprovação e os testes exigidos pelo repositório.
- Remova dados sensíveis de código, exemplos, screenshots, arquivos e histórico de commits.

A equipe responsável por cada projeto avaliará as contribuições conforme seu contexto e suas prioridades.

## Conduta e segurança

Mantenha as interações técnicas respeitosas e construtivas. Consulte o [Código de Conduta](https://github.com/SolutionIPD/.github/blob/main/CODE_OF_CONDUCT.md).

**Suspeitas de vulnerabilidades não devem ser publicadas em issues.** Veja [SECURITY.md](https://github.com/SolutionIPD/.github/blob/main/SECURITY.md) para o canal de reporte.
